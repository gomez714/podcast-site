## Ground rules (summary of AGENTS.md and spec §0)

- Never `git commit`, `git push`, merge, rebase, tag or open PRs. Leave changes uncommitted and summarize them; the owner commits.
- Next.js here is 16.4 with breaking changes from older versions. Read the relevant guide in `node_modules/next/dist/docs/` before writing Next.js code.
- `docs/THE_BOTTOM_LEFT_PANE_WEBSITE_SPEC.md` is the source of truth. Implement only the current phase (§11 tracks progress with dated notes; Phases 0–5 are largely done, Phase 6 is next). **Approved** items are requirements, **Proposed** items are defaults, **Unverified** items are things to test.
- Never invent guest bios, quotes, chapters, artwork, dates, platform URLs or episode-to-YouTube mappings. Editorial content must come from the show notes or the host.
- When finishing a phase task, record what was done and verified in spec §11, matching the style of existing entries.

## Commands

Use npm (Node 24). Run all four checks before reporting work as done:

```bash
npm run typecheck
npm run lint
npm run format:check      # npm run format to fix
npm test                  # vitest run
```

- Single test file: `npx vitest run tests/unit/show-notes.test.ts`
- Single test by name: `npx vitest run -t "part of the test name"`
- Dev server: `npm run dev`; production build: `npm run build`
- Tests live only in `tests/unit/**/*.test.ts` (node environment, `@` aliases `src/`). The RSS fixture is `tests/fixtures/fusebox-feed.xml`.

Data and asset scripts (run with `tsx`, from `scripts/`):

- `npm run sync:episodes` rewrites `src/data/episodes.snapshot.json` from the live feed (`-- --fixture` uses the test fixture). It refuses to write if the feed has errors or an episode GUID has no slug.
- `npm run fixture:refresh` re-downloads the feed fixture, redacting emails.
- `npm run assets:brand | assets:hero | assets:thumbnails` regenerate images from `assets/brand/` (and YouTube thumbnails into `public/images/episodes/` + `src/data/episode-thumbnails.json`).
- `npm run assets:host` crops and resizes host photos from `assets/hostPictures/` into `public/images/host/` (the crop boxes are hand-tuned in `scripts/build-host-photos.ts`).

## Architecture

**Episode data pipeline (no runtime dependency on the feed).** Fusebox RSS → `src/lib/rss/parse-feed.ts` (fast-xml-parser, uses `<content:encoded>` show notes, redacts emails) → `src/lib/episodes/normalize.ts` / `inventory.ts` (Zod-validated, deterministic newest-first sort, slugs attached from `src/content/episode-slugs.ts` keyed by RSS GUID) → committed snapshot `src/data/episodes.snapshot.json`. Slugs are hand-assigned and permanent.

**Hand-written vs generated.** `src/content/` is hand-written (slugs, per-episode editorial in `episodes.ts`: guest name, summary, topics, `youtubeId`, `contentNote`, `guestLinks`, `relatedSlugs`, `reviewStatus`, plus `featuredEpisodeSlugs`). `show.ts` and `host.ts` hold the host's own show and bio copy, which the homepage and About page share so they never drift apart; don't reword it. `src/data/` is generated by scripts; don't edit it by hand. The feed sync never touches `src/content/`.

**Repository is the only read path.** Pages read episodes through `src/lib/episodes/repository.ts` (`getAllEpisodes`, `getEpisodeBySlug`, `getFeaturedEpisodes`, `getRelatedEpisodes`), which joins snapshot + editorial + thumbnails into `EpisodeView` and throws `EpisodeInventoryError` on any mismatch (missing editorial, unknown slug, stale thumbnail), so inconsistencies fail the build. This layer exists so a later PostgreSQL migration (Phase 7) doesn't require rewriting pages. Show notes are parsed per episode by `src/lib/episodes/show-notes.ts` into description, takeaways and chapters (chapters seek audio only, since video edits differ in length).

**Rendering.** `next.config.ts` enables `cacheComponents` and `partialPrefetching`. Every episode slug is in `generateStaticParams`, and the episode page awaits `params` outside any Suspense boundary so it prerenders fully (an inner boundary shipped a loading skeleton ahead of the content and caused layout shift). `src/proxy.ts` (Next 16's replacement for middleware) rewrites unknown `/episodes/<slug>` to the not-found route before rendering, so a new slug must be in `episode-slugs.ts` to be reachable.

**Hidden pages stay alive.** Cache Components keeps up to 3 visited pages in the DOM, hidden with React `<Activity>` (see `node_modules/next/dist/docs/01-app/02-guides/preserving-ui-state.md`). So:

- Media must stop in an effect cleanup when its page is hidden (`AudioPlayer` pauses; `VideoEmbed` unloads its iframe).
- Element IDs on pages that can coexist must be unique per page. Episode IDs include the slug, and the About page passes its own IDs to the reused home sections.
- Don't target the sticky header with anchors: `#top` relies on the HTML default.

**Metadata and links.** Pages build metadata with `pageMetadata()` (`src/lib/metadata.ts`), which sets the canonical URL, Open Graph and X/Twitter tags together. Next merges metadata shallowly, so setting `openGraph` alone loses the layout's fields. JSON-LD builders live in `src/lib/structured-data.ts`, rendered via `components/seo/JsonLd`. Link arrows follow one convention:

- ↗ only for off-site links, all of which use `components/ui/external-link` (new tab, screen-reader notice).
- → for another page on the site.
- ↓ for a jump further down the same page.
- A copy icon for links whose URL is copied rather than opened (`components/ui/copy-link`; the footer's RSS feed).
- One deliberate exception: the homepage hero's "A new chapter is coming" jumps to `#revival` with a faint underline and no ↓ (host's choice). Don't add an arrow to it. Its red recording light (`.recording-light`, `--brand-rec`) is the site's only red accent (error states aside); don't reuse it elsewhere.

**Audio player.** `src/components/media/` wraps a native `<audio preload="metadata">` pointed directly at the Fusebox URL. UI state comes from a pure reducer in `src/lib/media/player-state.ts` driven only by media events (no optimistic "playing" state); seek/time helpers are in `src/lib/media/`. The server HTML is a plain `<audio controls>` fallback that the custom UI replaces after hydration. `EpisodeMedia` adds Listen/Watch tabs only when `youtubeId` exists; the YouTube (`youtube-nocookie.com`) iframe loads only after the poster is pressed, and switching tabs pauses the other medium.

**Hero.** `src/components/home/HeroArtwork.tsx` layers PNGs from `public/images/hero/` (built from `assets/brand/source/CoverArt.psd`) with an SVG door from `hero-geometry.json`, animated with SVG `<animate>` (no JS) and a still state under reduced motion.

**Styling.** Tailwind 4 (via `@tailwindcss/turbopack`) with brand tokens and shadcn semantic tokens in `src/app/globals.css`; shadcn/ui uses the Base UI primitives (`@base-ui/react`), not Radix. Site name, URLs, nav and verified platform links live in `src/lib/site.ts`. Env vars (`NEXT_PUBLIC_SITE_URL`, `PODCAST_RSS_URL`) are optional; see `.env.example`.

## Adding a new episode

1. `npm run sync:episodes` (fails until step 2 is done).
2. Add its GUID → slug to `src/content/episode-slugs.ts`.
3. Add its entry to `src/content/episodes.ts` (`reviewStatus: "draft"`).
4. If it has a filmed video, set `youtubeId` and run `npm run assets:thumbnails`.
5. After host review, set `reviewStatus: "reviewed"`. The review checklist is `docs/EPISODE_CONTENT_REVIEW.md`.
